@ Metroid Fusion (US) text charmap for tools/preproc's C INCTEXT path.
@
@ Encoding.  The engine stores text as little-endian u16 words
@ (src/text.c: TextDrawLocationTextCharacters takes a `const u16*`).  The
@ character glyph code is in the LOW byte: 'A' is the word 0x00C1.  Control
@ words use the HIGH byte: {NEW_LINE} is 0xFE00, {WIDTH(n)} is 0x80NN,
@ {INDENT(n)} is 0x83NN and CHAR_TERMINATOR is 0xFF00.  CHAR_MASK
@ (include/constants/text.h) tests that high byte only, which is why control
@ words can be recognised without disturbing the glyph codes.
@
@ preproc's ReadSequence treats a one-byte mapping as the high byte, so a
@ character row is written as two bytes: `'A' = 00 C1`, not `'A' = C1`.
@
@ Evidence (US text blob; ROM bytes are read for evidence and never committed).
@   0x086B489A: words 0093 00C5 00C3 00D5 00D2 00C9 00D4 00D9 0040 ...
@   That is "SECURITY LEVEL 1 UNLOCKED" with 0x00C5 = E, 0x00C3 = C,
@   0x00D5 = U, 0x00D4 = T, 0x0040 = space.  The same record contains
@   0x8012 (WIDTH) and ends in 0xFF00 (CHAR_TERMINATOR).  Note the raw byte
@   order: `C5 00` for E, `40 00` for space, `12 80` for WIDTH(n), and
@   `00 FF` for the terminator.
@
@ Only the proven, in-scope mappings are listed.  Unknown characters --
@ including all digits and punctuation -- make preproc fail on purpose.
@ Do not add guessed codes; prove them against a text blob or glyph first.
@
